# kas Lockfiles

This directory contains **kas lockfiles** — resolved build configurations with
all repository revisions pinned to specific commits.

## What are lockfiles?

A lockfile is generated by `kas dump --lock` and captures the exact state of
every repository at build time. This makes builds fully reproducible regardless
of upstream changes.

## Channel workflow

Lockfiles are generated per **channel** and **target**:

| Channel   | Source                  | Naming pattern                    |
|-----------|-------------------------|-----------------------------------|
| `nightly` | AUTOREV (latest commits)| `nightly-{mdb,dbc,rpi4}.lock.yml` |
| `testing` | Nightly lockfile        | `testing-{mdb,dbc,rpi4}.lock.yml` |
| `stable`  | Testing lockfile        | `stable-{mdb,dbc,rpi4}.lock.yml`  |

### How it works

1. **Nightly builds** use `kas build kas/<target>.yml` with AUTOREV, fetching
   the latest commits. After a successful build, a lockfile is dumped.

2. **Testing builds** use `kas build kas/lock/nightly-<target>.lock.yml`,
   building from the proven nightly revisions. On success, a testing lockfile
   is generated.

3. **Stable builds** use `kas build kas/lock/testing-<target>.lock.yml`,
   building from the promoted testing revisions. The final stable lockfile
   is included in the release.

## Generating lockfiles manually

```bash
# Generate a lockfile for MDB
kas dump --lock kas/mdb.yml > kas/lock/nightly-mdb.lock.yml

# Or use the helper script
./kas/generate-lockfiles.sh nightly
```

## Using lockfiles

```bash
# Build from a specific lockfile
kas build kas/lock/nightly-mdb.lock.yml

# The lockfile is a complete, self-contained kas config
# No network access needed to resolve revisions
```

## Notes

- Lockfiles are **generated artifacts**, not manually edited
- CI commits lockfiles to this directory after successful builds
- Lockfiles in this directory may be updated frequently (nightly)
- For release lockfiles, check the GitHub release assets
